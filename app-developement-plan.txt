# Argit - The Argit Electron App - Complete Development Specification

## Project Overview
A desktop personal finance tracking application built with Electron for Linux (EndeavourOS) that provides simple, automatic money management with real-time balance updates and intelligent subscription tracking.

## Core Requirements

### Primary Functionality
1. **Transaction Management**
   - Add income transactions with automatic balance increase (+)
   - Add expense transactions with automatic balance decrease (-)
   - Real-time balance calculation and display
   - Transaction history with date stamps
   - Ability to remove/delete transactions with automatic balance adjustment

2. **Balance Tracking**
   - Prominent display of current account balance
   - Automatic updates when transactions are added/removed
   - Visual indicators for positive/negative balance states
   - Balance persistence between app sessions

3. **Subscription Management**
   - Add recurring subscriptions with name, amount, and bill date
   - Smart bill date calculation (next upcoming date logic)
   - If today's date < bill date → next bill is this month
   - If today's date >= bill date → next bill is next month
   - Display total monthly subscription costs
   - Remove/edit subscriptions

4. **Monthly Focus**
   - Display current month and year prominently
   - Filter transactions to current month only
   - Monthly income/expense summaries
   - Reset or archive data monthly (optional feature)

## Technical Architecture

### Framework Stack
- **Frontend**: React 18+ with modern hooks (useState, useEffect)

## Detailed Feature Specifications

### 1. Transaction System
**Input Fields:**
- Transaction type: Dropdown (Income/Expense)
- Amount: Number input (decimal precision to 2 places)
- Description: Text input (required, max 100 characters)
- Date: Auto-filled with current date, editable

**Validation:**
- Amount must be positive number > 0
- Description cannot be empty
- Date must be valid format

**Display:**
- Reverse chronological order (newest first)
- Color coding: Green for income (+), Red for expenses (-)
- Show date, description, and amount
- Delete button for each transaction
- Scrollable list with max height

### 2. Balance Management
**Display Requirements:**
- Large, prominent number display
- Currency formatting ($X,XXX.XX)
- Color coding: Green for positive, Red for negative, Yellow for zero
- Smooth transitions when balance updates
- Backup/restore balance feature

**Calculation Logic:**
- Starting balance (user settable, default 0)
- Balance = Starting Balance + Total Income - Total Expenses
- Real-time recalculation on any transaction change
- Persistence across app restarts

### 3. Subscription Intelligence
**Smart Date Logic Implementation:**
```javascript
function getNextBillDate(billDay) {
  const today = new Date();
  const currentMonth = today.getMonth();
  const currentYear = today.getFullYear();
  const todayDate = today.getDate();
  
  let nextBillDate;
  
  if (todayDate < billDay) {
    // Bill hasn't occurred this month
    nextBillDate = new Date(currentYear, currentMonth, billDay);
  } else {
    // Bill has passed, next one is next month
    nextBillDate = new Date(currentYear, currentMonth + 1, billDay);
  }
  
  return nextBillDate;
}
```

**Display Features:**
- Subscription name and monthly cost
- Next bill date prominently displayed
- Days until next bill (optional)
- Total monthly subscription cost summary
- Sort by next bill date or alphabetically

### 4. Monthly Statistics Dashboard
**Key Metrics:**
- Total monthly income
- Total monthly expenses
- Net income (income - expenses)
- Subscription costs
- Average transaction size
- Transaction count

**Visual Elements:**
- Card-based layout
- Color-coded metrics
- Progress bars or simple charts (optional)
- Month navigation (current month focus)

## Native Theme Integration (Optional Feature)

### System Theme Detection
**Requirements:**
- Detect Linux desktop environment theme (GNOME, KDE, XFCE)
- Support both light and dark themes
- Real-time theme switching when system changes
- Fallback to manual theme selection

**Implementation Approach:**
```javascript
// In main process (main.js)
const { nativeTheme } = require('electron');

function getCurrentSystemTheme() {
  return nativeTheme.shouldUseDarkColors ? 'dark' : 'light';
}

// Watch for theme changes
nativeTheme.on('updated', () => {
  const theme = getCurrentSystemTheme();
  // Send theme update to renderer process
  mainWindow.webContents.send('theme-changed', theme);
});
```

**Theme Variables:**
```css
/* CSS Custom Properties for theming */
:root {
  --bg-primary: #ffffff;
  --bg-secondary: #f8f9fa;
  --text-primary: #1a1a1a;

  --error-color: #ef4444;
}

[data-theme="dark"] {
  --bg-primary: #1a1a1a;

  --text-primary: #ffffff;
```
